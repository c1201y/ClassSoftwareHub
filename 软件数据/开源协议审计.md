> 面向维护者。本文只讲事实与**建议动作**，不构成法律意见。

> NOASSERTION 的几个另外读了仓库根目录的许可文件正文。统计口径为 2026-11-01 当天的 131 个软件。

## 一、先看结论

本站的分发方式决定风险等级。**只做直链索引**（用户点下载跳到官方/GitHub）时，
GPL、AGPL 那些「必须提供源码」的义务基本不触发 —— 我们没有复制、没有重打包、也没有托管文件。

真正会咬人的只有一种：**把别人的安装包复制到我们自己的对象存储里对外分发**。
这是再分发，协议允许不允许、有没有源码义务，全看那一份许可。

目前有 **7 个软件**是这种分发方式（下载地址以 `oss://` 开头）。逐个核对下来：

| 等级 | 软件 | 许可 | 状况 | 处置（2026-11-01 已执行） |
| --- | --- | --- | --- | --- |

## 四、常设规则

1. **默认只做直链索引**。任何「把安装包复制到本站 OSS」的想法，先查那份许可给不给再分发权。
2. **GPL / AGPL 的软件如果转存本站**，必须同时提供对应源码（AGPL 还包括网络使用者的获取渠道）。
3. **MIT / Apache / BSD 如果转存本站**，必须保留原版权声明与许可文本 —— 至少详情页要给出仓库地址与协议名。
4. **没有 LICENSE 的仓库按「保留所有权利」对待**，转存前必须取得作者同意。
5. 投稿上传的文件由投稿者声明权利；站内已有免责声明说明「文件由投稿者上传，本站未作修改」，
   但这**不能替代**对 PYAS 这类明文禁止再分发的处理。

## 五、相关字段

从 2026-11-01 起，软件数据支持两个可选字段（投稿表单里也能填）：

| 字段 | 含义 | 显示位置 |
| --- | --- | --- |
| `author` | 开发者名称（个人或团队） | 详情页「详细信息」区，有值才显示 |
| `license` | 开源协议（SPDX 标识或全名，如 `MIT`、`GPL-3.0`） | 同上 |

### 当前覆盖（2026-11-01 全量补齐）

129 个在列软件里，**`author` 覆盖 125 个**、`license` 覆盖 67 个。口径如下：

- **有 GitHub 仓库的 73 个**：`author` 取仓库所有者账号名（`owner.login`，API 直出、可核验），
  `license` 取 `license.spdx_id`。GitHub 认不出来（`NOASSERTION` / `null`）的逐个读了仓库许可文件正文，
  结论见第三节。**确认没有许可文件的 7 个不写该字段**（Supermium、CountBoard、FluentView、
  Microsoft.Net.Packages.AIO、PixLens、Seewo-Custom_Start），⛔ 不臆测。
- **没有 GitHub 的 56 个**：其中 52 个的 `author` 填发行方名称（如 `金山办公`、`腾讯`、`Microsoft`、
  `希沃（视源股份）`），`license` 一律不填 —— 这批是商业软件或未公开许可的产品，
  写个「专有软件」进去只是让详情页多一行废话。
- **刻意留空的 4 个**：`author` 拿不准的一律不填 —— DirectX 修复工具、Dism 图形界面、Easy PDF、
  手心输入法（这四个只有第三方下载站线索，找不到明确发行方）。

### 两个需要留意的特例

- **PYAS**：`license` 写的是 `Source Available（非开源）`。这是刻意的 —— 它不是开源许可，
  而且明文禁止再分发，让人一眼看出性质比填个协议名重要。
- **Everything**：原来 `github` 指向 `voidtools/Everything`，**那个仓库并不存在**（API 404，
  该账号下只有 `everything_sdk3` 一类衍生库）。已删除该字段，改成 `author: voidtools`，
  免得详情页给用户一个 404 的按钮。

### 关于「本站对象存储里的副本」

改链接**不删除**文件本身。OSS 上那 10 个对象（7 个软件、10 条链接）在被引用之前一直占着空间，
要不要真删由维护者在控制台决定 —— 那一步不可逆，本文不做建议。

⛔ 注意不能只删 OSS 文件而留着链接：那会让详情页出现「点下载 404」的死链，比现在更难排查。
顺序一定是**先改链接、再清文件**。

### 一处顺带修掉的历史错误

`everything.json` 的 `github` 一直指向 `voidtools/Everything`，而那个仓库**根本不存在**
（2026-11-01 用 API 核实：`/users/voidtools` 存在、12 个公开仓库，没有 `Everything`）。
已删除该字段。详情页因此不再显示一个必然 404 的「GitHub」按钮。

## 七、复跑方式

审计是一次性的，但软件列表会变。要重跑：

```bash
# 1. 提取全部 github 字段
# 2. 逐个调 GitHub REST API 的 license.spdx_id
# 3. NOASSERTION 的再读仓库根目录许可文件正文
```

GitHub 未登录接口只有 60 次/小时，脚本里带上 token（本机 `git credential fill` 取到的那把，5000 次/小时）。
⚠️ 本机 `raw.githubusercontent.com` 直连不通，读文件正文要走 API 的 base64 `content` 字段，**不要**用 `download_url`。
