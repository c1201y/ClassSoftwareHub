# 回声洞

QQ 群里那些让人笑出声的沙雕发言。**一条一个文件**，全部放在 `messages/` 目录下。

## 投稿

**推荐：在网站上投稿。** 打开站点的「设置 → 关于 → 回声洞」，点「投稿」，写一句提交即可。

投稿不会直接上线：它会先落成一份**审核草稿**，维护者审核通过后才收进本目录。
草稿由提交服务（Cloudflare Worker `classhub` 的 `/api/echocave`）写进
`submissions/echo-<时间戳>-<随机>.json`，内容形如：

```json
{
  "_类型": "回声洞",
  "text": "要收录的发言",
  "_提交时间": "2026-10-04T02:00:00.000Z"
}
```

**手动投稿**（网站投稿服务连不上时的兜底）：在 `submissions/` 下新建一个 `.json`
（文件名随意，建议 `echo-<时间戳>.json`），按上面的形状写，`_类型` 那一行**不能少** ——
审核脚本靠它认出这是回声洞投稿。然后提交分支 → 开一个 PR。

> 上限 200 字。

## 审核之后

维护者在草稿对应的 Issue 上打标签：

- `approved` → 由 `.github/workflows/review-submission.yml` 写入 `messages/messageN.json`，
  N 取当前最大编号 + 1（内容只留 `text`，两格缩进）；随后自动构建上线。
- `rejected` → 直接删掉草稿。

> 编号不要重复、不要跳号复用；网站、桌面应用、CSHcontroller 都按文件名里的数字排序。

维护者也可以手工在 `messages/` 里新建 / 删除字条（跳过审核，直接生效）。

## 为什么改成一条一个文件

- 加一条 = 新增一个文件，删一条 = 删一个文件。改动面小，多人同时投稿也不会撞车。
- 网页端、桌面应用、CSHcontroller 控制台读的是同一套目录，格式统一。

## 怎么查内容

在 GitHub 网页上只能看到 `message1`、`message2` 这样的文件名，看不到写了什么。
要查看或搜索具体内容，用 **CSHcontroller 控制台的「回声洞」页**——那里有列表和搜索框。
